# 职途 JobPilot · AI 求职陪跑 Agent

> 一个有记忆、会追问、能陪跑的 AI 求职 Agent —— 把每一次面试失分，变成下一步的行动。

全国高校 AI Web 开发挑战赛参赛作品（AI Agent 智能助手方向）。

---

## 一、项目介绍

### 解决什么问题

求职是长达数月的多轮过程，但现有工具是割裂的：改简历一个网站、刷题一个 App、复盘靠脑子。**上一场的弱点，下一场没人记得。**

- 改完简历还是没回音 —— 工具只给话术建议，不知道目标岗位到底要什么
- 背了 100 题，一追问就崩 —— 静态题库与你的简历无关，答完没有追问
- 面完只记得"好像答得不好" —— 没有记录、没有归因，同一个错误反复出现

### 我们的方案

JobPilot 把求职做成一个**数据闭环**：

```
简历解析 → 岗位对齐 → 模拟面试 → 时间轴复盘 → 学习补齐 → 下一场面试（带着记忆）
```

| 核心能力 | 说明 |
| --- | --- |
| 标准对齐诊断 | 简历按《全岗位通用简历评分标准》五维打分（岗位相关性 20 / 技术深度 25 / 关键词覆盖 15 / 量化证据 25 / 结构清晰度 15），每维给出 `实得分/满分` 与档位判断 |
| 可解释匹配 | 不给"匹配度 78%"这种黑盒数字，而是逐条列出命中 / 半命中 / 缺口，并附简历与 JD 原文引用 |
| 追问树 Agent | 问题来自你的回答：缺数据就追问指标，只报名词就追问实现与选型，最多两层纵深 |
| 动态能力雷达 | 五维能力（相关性/证据/深度/结构/反思）随面试实时变化，跨会话沉淀为弱点图谱 |
| 引用强制 | 每条结论都挂着原文引用，检索不到就明说"暂无资料"，不编造 |
| 确定性面试评分 | 固定 rubric：相同回答永远得到相同分数，每条扣分都有规则出处 |
| 隐私优先 | 简历只存浏览器 localStorage，送入模型前自动脱敏手机号/邮箱/证件号 |

## 二、快速开始

本项目提供两种交付形态，按场景选择：

| 形态 | 入口 | 适用场景 | 依赖 |
| --- | --- | --- | --- |
| 单文件网页版 | 根目录 `index.html` | 本地演示、评审快速查看、静态托管 | 无（双击浏览器打开） |
| Next.js 工程版 | `jobpilot/` 目录 | 公网部署、完整 AI 接口与在线演示 | Node.js ≥ 18.17 |

### 方式 A：直接打开网页（推荐用于演示）

双击根目录的 **`index.html`** 即可。所有页面、样式与交互都打包在这一个文件里，
不需要安装 Node、不需要命令行、不需要联网，简历与面试数据只存浏览器 localStorage。

也可以把 `index.html` 直接上传到任意静态托管（GitHub Pages / Vercel 静态站点），即得到一个可访问网址。

### 方式 B：运行 Next.js 工程版

```bash
cd jobpilot
npm install
npm run dev        # 开发模式 → http://localhost:3210

npm run build      # 生产构建
npm start          # 生产运行 → http://localhost:3210
npm run typecheck  # 类型检查
```

Windows 下也可以双击 `jobpilot/启动应用.bat`，它会自动检测 Node、安装依赖并启动开发服务。
**这只是开发者的启动脚本，不是网页本体**；网页交付物是根目录的 `index.html` 与 Next.js 工程本身。

### 模型配置（可选，仅工程版）

应用内置两种模型接入方式，均可在「设置 → 模型接入」中切换：

| 方式 | 配置 | 说明 |
| --- | --- | --- |
| 内置模型 | `jobpilot/.env.local` 写入 `DEEPSEEK_API_KEY=sk-xxx` | 部署方提供，开箱即用 |
| 自定义 Key | 设置页粘贴自己的 DeepSeek Key，验证后生效 | Key 仅存本机浏览器，服务器不落盘 |
| 无 Key | 无需任何配置 | 自动降级为本地确定性引擎，全流程可完整演示 |

`.env.local` 已在 `.gitignore` 中排除，**请勿将 Key 提交到仓库**。

## 三、技术架构

### 技术栈

- **框架**：Next.js 15（App Router）+ React 19 + TypeScript（strict）
- **样式**：Tailwind CSS 3.4（自研设计系统：brand/ink/hit/partial/gap 语义色）
- **状态**：Zustand 5（persist 到 localStorage，skipHydration 避免 SSR 水合不一致）
- **大模型**：DeepSeek（OpenAI 兼容协议，`response_format: json_object` 结构化输出）
- **文档解析**：pdfjs-dist（按文本坐标还原行结构）+ pdf-parse 兜底

### AI 技术方案（对应赛题评分点）

| 评分点 | 实现 |
| --- | --- |
| 大模型集成 8% | System Prompt 约束 + JSON Mode 结构化输出 + 30s 超时熔断 + 本地引擎兜底；简历解析与简历诊断均由 DeepSeek 语义增强，输出经 schema 校验后归一化 |
| Agent/工作流 8% | 面试状态机（warmup → deep_dive → stress → candidate_qa → end）+ 追问树决策（最多 2 层）+ 跨会话记忆 |
| RAG 6% | 中文 bigram + BM25 轻量检索，三库（岗位 JD / 题库 / 学习资料），检索结果驱动选题与任务生成 |
| 多模态 5% | PDF/TXT 简历解析（pdfjs-dist 按坐标还原版面 + 扫描件识别）；Web Speech API 语音识别作答 + TTS 播报 |
| AI 安全 4% | PII 脱敏（手机号/邮箱/证件号）后再送模型；面试评分走确定性 rubric，简历诊断的 LLM 输出经 schema 校验；无引用即标注"暂无资料" |
| MCP/工具集成 4% | Function Calling 风格的结构化工具协议（检索题库、评分、弱点合并），NDJSON 流式事件 `tool/token/meta/done` |

### 简历诊断：双通道打分

简历诊断分两层，兼顾"像真人 HR 一样读"与"任何环境都能跑"：

| 通道 | 触发条件 | 特点 |
| --- | --- | --- |
| LLM 诊断（主） | 内置 Key 或用户自定义 Key 可用 | 把目标岗位 JD + 脱敏简历送入 DeepSeek，System Prompt 内嵌评分标准的五维档位（优秀/及格/不合格），返回结构化 JSON：五维 `raw/max`、总评、按优先级排序的问题清单（含简历原文引用与改写句式） |
| 本地诊断（兜底） | 无 Key / LLM 返回非法 JSON / 超时 | 纯规则计算：技能命中率、深度关键词命中、量化 bullet 比例、模块齐全度，结果完全确定可复现 |

无论走哪条通道，前端展示口径一致：五维进度条显示 `实得分/满分`（如 `16/20`），综合得分为五维原始分之和（满分 100）。

### 关键设计：为什么面试评分不用 LLM

面试评分最容易被质疑"AI 打分随机"。JobPilot 的做法是 **规则打底 + LLM 增强**：

- 面试评分：固定 rubric（量化数字个数、技术术语命中、因果/分点/反思词检测），同一回答永远同分，扣分理由可解释
- 简历诊断：LLM 按标准打分，但输出经 schema 校验并归一化（维度数必须为 5、分数强制转数字、问题截断 6 条），非法即回落本地规则
- LLM 只负责"问得更像真人"以及简历语义增强；失败自动回落本地引擎，Demo 模式全流程可用

### PDF 识别优化

简历上传支持 PDF / TXT，PDF 走专门的处理链路：

1. 用 pdfjs-dist 逐页提取文本项，按 `(y, x)` 坐标还原行与列顺序，解决双栏简历串行问题
2. 自动识别并剔除跨页重复的页眉/页脚
3. 清洗多余空白、合并破碎行、过滤纯页码行
4. 若文本层为空（扫描件/图片 PDF），明确提示改用「粘贴文本」，而不是给出一个空结果
5. pdfjs 异常时回退 pdf-parse，保证解析链路不中断

## 五、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击 `index.html` 没反应 / 打开是源码 | 文件被系统用编辑器打开。右键 → 打开方式 → 选择 Chrome / Edge 等浏览器 |
| 单文件版能否联网使用大模型 | 可以。在「设置」里填入自己的 DeepSeek Key 即可；不填则走本地确定性引擎，功能完整可演示 |
| 访问 `localhost:3210` 打不开 | 端口被占用。用 `netstat -ano \| findstr :3210` 找到占用进程并结束，或把 `package.json` 中 `dev` 脚本的 `-p 3210` 改成其它端口 |
| 页面报 "missing required error components" / 白屏 | `.next` 缓存损坏。先停止服务，删除 `.next` 目录后重新 `npm run dev` |
| 上传 PDF 提示"扫描件" | 该 PDF 没有文本层（图片扫描）。改用「粘贴文本」导入，或导出为可复制文字的 PDF |
| 诊断分数全为 0 | 简历正文为空。请确认导入后简历内容区有文本，再点击诊断 |
| 面试页发送按钮一直是灰的 | 面试官开场尚未完成。等开场问题出现后再作答；若长时间无开场，刷新页面重试 |
| 右上角显示 "Demo 模式" | 未检测到可用 Key。应用会使用本地确定性引擎，流程可完整演示；如需真实模型，在「设置 → 模型接入」填入 DeepSeek Key |
| `启动应用.bat` 是做什么的 | 仅用于启动 Next.js 开发服务器；网页交付物是 `index.html` 与工程代码，不是这个脚本 |
